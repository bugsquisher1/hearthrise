# Balance baseline 09: the model graph

Lane `lane/lab-p1-picture` (systems engineer, 2026-11-21). Phase 1, "Picture", of the unified Balance Lab (`docs/design/redesign/07-balance-lab.md`, section 3.1, section 3.8 and the roadmap row "1. Picture"). Tools, tests and this page only. No gameplay data, formula or engine line changed.

**The aim.** Nobody tunes one number again without seeing everything it touches.

**Labels.** DERIVED means read from the rule code by a tool, with a file and a line. DECLARED means written by a person, with a reason. MEASURED means a played run on the real engine, named. JUDGED means this lane's reading. The tables between `graph:` marks are generated by `node tools/balance-program/graph.mjs --write` and are never edited by hand.

**Where it lives.**

| File | What it is | Who writes it |
|---|---|---|
| `tools/balance-program/graph/quantities.mjs` | The closed list of quantities, each with the names the rule code spells it by | A person |
| `tools/balance-program/graph/io.mjs` | The typed reads and writes of every formula in the register, the outcome readers, the interaction records | A person |
| `tools/balance-program/graph/moves.mjs` | What each knob and each lever moves when it is raised | A person, where it cannot be derived |
| `tools/balance-program/graph/derive.mjs` | Reads the rule code: what a formula's home really touches | Code |
| `tools/balance-program/graph/build.mjs`, `trace.mjs`, `measured.mjs` | The join, the trace with polarity, the compare against measurement | Code |
| `tools/balance-program/graph/measured.json` | Measured movement, in one shape | `graph.mjs --measure` |
| `tools/balance-program/graph.json` | The joined picture | `graph.mjs --write` |
| `tools/balance-program/graph-findings.json` | The findings that are known today | `graph.mjs --write --accept` |
| `tools/balance-program/graph.mjs` | Builds, writes, checks, proves | |
| `tools/balance-program/lab.mjs` | `lab ask` and `lab propose` | |

The builder is `graph.mjs` and not `model.mjs`, because `tools/balance-program/model.mjs` already exists (the economy model's ledgers). The spec's folder `tools/balance-lab/` already holds the Balance Lab page, so the command line lives beside the registers it reads.

No fact is copied. The formulas and their edges stay in `formulas-architecture.json`. The levers stay in `levers.json`. The targets stay in `targets.json`. This lane adds the typed layer on top and the join.

**A quantity** is a named amount a mechanic consumes or produces: a hero's largest blow, a monster's HP, a kill's XP, a price. The 19 outcomes the matrix measures are quantities too, with the matrix's own ids. One more, `fight.share`, is the share of hunted time spent in a fight. No formula computes it and no metric prints it, and the graph needs it to connect the two.

**A read** has a direction. `+q` means raising q raises what the formula writes. `-q` lowers it. `~q` moves it and the direction depends on the case. `!q` is an offline dependency: a table that was measured or typed from q by hand and is not re-read when q moves. `@+q` is a career read: it acts between hunts, never inside one (earned XP becoming a Level). `+q>w` limits the read to one of the formula's writes.

**How each fact is obtained.**

| Fact | How | What stops it going wrong |
|---|---|---|
| Which code a formula lives in | DECLARED once, by binding name (`file#binding`, or `file#TABLE.key` for one key of a shared table), so a moved line changes nothing | A binding that is gone fails the check |
| That a formula touches a quantity | DERIVED: the tool reads the home with the TypeScript parser and finds the quantity's names in it, as a read or as a write | A name in the home that no declaration covers fails the check |
| A read or write the code cannot show (an argument, a table row) | DECLARED, with the reason written beside it | A declaration with no reason and no name in the home fails the check |
| The direction of a read | DECLARED. It is JUDGED from the register's text and the code | The sign-match rate against measurement (section 5) |
| Which formulas call into which | DERIVED: identifiers resolved through the file's imports | |
| Which formulas read a lever's number | DERIVED the same way, down to the key of a table | |
| What a lever moves | DERIVED from its knob, or from its formula when that writes one quantity. DECLARED for the rest | A lever said to move a quantity its formulas do not write fails the check |
| What a measured outcome follows | DECLARED: 17 outcome readers. They stand where the register's row E14 stands ("No formula computes these") | The sign-match rate |
| Which outcomes a target reads | DERIVED from the words of its reader bands in `standards.mjs` | A target that reaches no outcome is listed in section 8 |

**The check.** `node tools/balance-program/graph.mjs --check` is registered in CI beside the lever check (`economy-selftests`).

- A PROBLEM fails it outright: a formula with no typed row, a quantity off the list, a lost home, an undeclared read or write in rule code, a wrong declaration, a lever said to move what its formulas do not write, a stale record.
- A FINDING has a stable id made from its kind and its pair, never from a line number. Today's findings are the baseline. A new one fails the check. One that is gone must be dropped with `--write`. Only `--write --accept` adds to the baseline, and that is a person's decision.
- A moved line fails nothing. A new content file fails nothing.

**How to read it.** A measured size is the change between the lowest and the highest played step, as a share of the largest of the three values, at the median moved cell. It is a size between two steps, not a slope at one point. The lever declares 9 outcomes. The sweep moved 10 more. A raise of monster HP raises Level XP an hour, because a kill's XP is priced by the hit point and the hunt spends more of its hour fighting. The graph calls that at depth 3 and prints the depth 4 path that argues the other way.

`ask` also takes a lever id, a formula id, a quantity, an outcome and a target. A target prints every lever that reaches it, the measured size first. `lab propose monsterHp=1.1 xpPerKill=0.9` prints what both changes move together, each change's share in every outcome, a predicted size, the outcomes nobody declared, the targets touched, and the cells, scopes and tests to re-run. It carries a warning when a lever in the proposal was found dead.

**How a direction is predicted.** A quantity's depth is the fewest mechanics between the lever and it. Its predicted direction is the direction of its shortest paths. If two shortest paths disagree the answer is "mixed" and the graph does not call it. A longer path that disagrees is kept and printed as the counter-path. This is a reading of a graph. It knows directions, never sizes.

**The first run and what was fixed.** The stop rule says that under two thirds the register is wrong and gets fixed before anything is built on it. The first run matched 247 of 268 calls, 92%, with 21 misses. Three went when the homes of the first draft were corrected and were not recorded one by one. The other 18 were read one by one. This is what they were.

| Misses | Cause | What was done |
|---|---|---|
| 8, on `monsterHp`, `partyGroundHp` and `tierHp` | This lane's row for C-PULL let a monster's HP feed the pull size. It feeds only the HP a monster stands with | Fixed: each read of C-PULL is limited to the write it reaches |
| 4, on `tierDanger` and `heroHp` | Two rows passed a direction where none flows inside a hunt: through earned XP becoming skill, and through the unrelated reads of the cast resolver | Fixed: career reads are marked and not traced inside a hunt. The cast resolver `effect` is now a shared home of the formulas it serves, and C-AREA reads only what decides how many it hits |
| 1, `attackInterval` on low HP | The low-HP reader did not read the swing clock. Monsters swing on the same clock as heroes, so slower swings are less burst | A read was added to the reader, with that reason. It fixed this miss and uncovered one on the same knob, which is kept below |
| 5, on `heroHp` | A real second-order effect | Kept as findings, below |

## 7. Ghost edges, ranked

A ghost edge is a pair of mechanics that share a quantity or a call with no declared interaction. The idea is mechflow's, rebuilt here with no code from it.

<!-- graph:findings -->
| Kind | What it is | Count |
|---|---|---|
| `feeds` | ghost edge: one writes what the other reads, no declared edge | 133 |
| `writers` | ghost edge: two mechanics write one quantity, no declared edge | 61 |
| `carrier` | ghost edge: a declared edge with no shared quantity | 48 |
| `call` | ghost edge: the code calls it, no declared read | 15 |
| `lever-reader` | a lever's number is read by a formula the lever does not name | 8 |
| `sign` | the trace's predicted direction disagrees with the measured one | 8 |
| `undeclared-move` | a measured movement no lever declared | 75 |
| `dead` | a played lever that moved nothing | 4 |
| `dead-outcome` | a declared outcome that did not move | 42 |
<!-- /graph:findings -->

| Kind | What it means | How to answer it |
|---|---|---|
| `feeds` | One formula writes what another reads, and the register holds no edge between them | Add the edge to the register, or write a `NO_INTERACTION` record with the reason |
| `writers` | Two formulas write the same quantity with no edge. Two numbers stack on one amount | The same. This is the kind the dominance check will care about |
| `carrier` | The register says A feeds B, and A writes nothing B reads | Name the quantity in `io.mjs`, or drop the edge. Many of these are an edge that skips a step: the register says armor feeds the supply bill, and the quantity goes through the landed blow |
| `call` | The code of one formula reaches into another's home, and no quantity is declared between them | Declare the read, or write the record |

Two formulas that only read the same quantity are not a ghost edge. Half the game reads the hero's Level.

The rank is the number of levers on the pair: the more numbers an agent can tune there, the more it costs not to know the two interact.

## 9. Room for what comes next

**Trait pairs.** Items will carry up to two Traits from weighted, gated pools (`docs/design/redesign/02-architecture.md` section 2c). The graph's shape already holds them. Every declared pair is one row of `interactions` in `graph.json`: `{ id, kind, members, q, sign, because, source }`. The kinds are `feeds`, `stacks`, `excludes` and `pair`. The node kinds are `formula`, `reader`, `lever`, `target` and `trait`. A Trait pair is a row of kind `pair` whose members are `trait:<id>`. The selftest plants one and proves nothing else changes. The dominance check can read pairs from that list when Traits exist. Nothing about Traits is built here.

**The sensitivity matrix.** Section 6.

**The gate.** The roadmap's phase 7 wants a red check on a balance change with no record. `--check` already fails a balance change that makes rule code touch a quantity nobody declared, and `lab propose` takes the patch file such a record would name.

## 10. Keeping it true

| When this happens | Do this |
|---|---|
| `--check` says a home reads or writes a name nobody declared | Add the read or the write to the formula's row in `io.mjs`. If the name is not that quantity there, say what it is with `as`, or `skip` it with the reason |
| It says a declaration is not shown by the code | Give the reason in the row, or remove the declaration |
| It says a new finding | Read it. Add the edge to the register, write a `NO_INTERACTION` record, or accept it with `--write --accept` and say why in the commit |
| It says a baseline finding is gone, or `graph.json` is stale | `node tools/balance-program/graph.mjs --write` |
| A formula is added to the register | Give it a row in `io.mjs`. The check fails until it has one |
| A lever is added | It needs nothing if it has a knob or its formula writes one quantity. Else a row in `moves.mjs` |
| New measured data lands | `node tools/balance-program/graph.mjs --measure <folder or file>`, then `--write` |

`node tools/balance-program/graph.mjs --findings [kind]` lists every finding with its id.
