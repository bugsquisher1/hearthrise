# Hearthrise Art Bible

For Tyler, making art by hand in PixelLab without Claude. Audit date 2026-10-15, build b588. It describes what exists; it adds no new art direction.

The rules come from code and from the existing docs. When this file and one of these disagree, the code or doc wins and this file gets fixed:
- `docs/ART_DIRECTION.md`: the look
- `docs/ASSET_STANDARDS.md`: sizes, sheets, anchors
- `docs/PIXELLAB_WORKFLOW.md`: the generation pipeline
- `src/data/world/art-budget.js`: size classes, the law
- `art/world/palette.json`: the 56-colour palette, the law
- `tests/world-assets.mjs` and `tests/pixel-icons.mjs`: the guards

**How to read the labels.** **VERIFIED** = read from a recorded PixelLab request (the `pixellab` block in the sidecars `art/world/<set>/<id>.json`) or from code. **NOT RECORDED** = the setting was used but nobody saved it. **UNVERIFIED** = my best understanding, which you need to check. PixelLab's documentation could not be reached from this session, so every name of a website menu or button below is UNVERIFIED. The API tool names and parameters are VERIFIED.

## 0. Folders

| Folder | What it's for |
|---|---|
| `art/reference/` | **The official style references.** Each one is a single frame cut from shipped art, saved at native size and at `@4x` (nearest-neighbour). In PixelLab, upload the `@4x` file if it rejects tiny images; otherwise use the native one. Never edit these files. |
| `art/inbox/` | **Your drop folder.** Put PixelLab exports here (see §8 for names). Claude picks them up, palette-locks them, builds and checks them, and moves them into `art/world/<set>/` or `assets/icons-bundle/pixel/items/`. Nothing in the inbox is loaded by the game. |
| `art/world/<set>/` | The shipped source sheets and sidecars (sets: `hero`, `town`, `home`, `cellar`). Don't drop files here by hand. |
| `assets/world/` | The built atlases. Generated by a script; never edit by hand. |

To get files to Claude in a cloud session, they must be **pushed**: on GitHub, open `art/inbox/` → Add file → Upload files → commit to a branch (for example `art/inbox-<date>`). Locally, `git add art/inbox && git commit && git push`.

## 1. The established style (measured, not invented)

| Property | Standard | Source |
|---|---|---|
| Perspective | **3/4 top-down**, called "high top-down" in PixelLab. Front faces visible plus the top. Never side-on, never isometric (diamond/corner-on art gets rejected by `validate.mjs` as "iso-corner"). | ART_DIRECTION §2; `chest.json` and `rug.json` notes |
| Grid | **32 art px = 1 tile.** Shown at ×2 (×3 on very wide screens), whole-number zoom only, no smoothing. | `art-budget.js` `T=32` |
| Proportions | Hero body 36–40 px tall (about 1.2 tiles, adult proportions, not chibi). Critters 12–20 px, beasts 40–48 px wide, door 48 px, trees 96–128 px. | `CLASSES` |
| Palette | **`hr-world-56-v2`**: 56 colours in 18 ramps (shadow, stone, earth, leaf, moss, bone, water, cloth, skin, torch, blood, frost, venom, gold, bronze, iron, steel, mithril). Every opaque pixel must be one of these colours. Swatch: `art/reference/palette_hr-world-56-v2.png`. | `art/world/palette.json` |
| Colour mood | **Gritty, muted and earthy.** Desaturated by material on lock (stone and terrain ×0.7 saturation, foliage ×0.75, characters ×0.85). Saturated accents (torch, blood, frost, venom, gold) are only for light, magic, loot and blood. | `src/data/world/palette.js` |
| Light | **From the upper left.** Highlights sit on the top and left; the down-right side is darker. | ART_DIRECTION §2 |
| Shadows | **Never painted into the sprite.** The engine draws them. Erase any baked shadow, ground patch or grass under the object (the oak had one erased). | `oak.json` notes; ALPHA_CUT |
| Outline | **One dark, single-colour outline** on every world sprite and icon ("single color black outline" for characters, "single color outline" for map objects). | sidecars |
| Shading | "detailed shading", "high detail": stepped bands, no dithering noise, no gradients. | sidecars |
| Alpha | **Binary only**: fully opaque or fully transparent. No soft edges, no anti-aliasing, no glow. | `ALPHA_CUT = 128` |
| Detail level | A reading prop at 32 px has 3–5 value steps per material and a clear silhouette. Item icons are 32×32 and fill 75–94% of the canvas. | ART_DIRECTION §7 |

**The art in one sentence:** a muted, gritty medieval world at 32 px per tile in 3/4 top-down view, lit from the upper left, with one dark outline, adult proportions, no baked shadows, and a strict 56-colour palette.

### 1.1 Inconsistencies found
1. **Three icon languages at once.** The 32 px pixel items (`assets/icons-bundle/pixel/items`, active) sit beside the painted Hearthfire/Recraft art (`assets/icons-bundle/hearthfire`, `painted/`, `assets/items/`, `assets/avatars/`) and the SVG line icons (`assets/icons/`). **Only the pixel language is the target.** Don't use painted or SVG art as a PixelLab reference.
2. **Two different `view` values in the prop requests.** Props from `create_1_direction_object` used `view: "top-down"` with "seen from the front and slightly above" in the text. Map objects, characters and monsters used `"high top-down"`. The results match visually because of the prompt wording. For new work, use **high top-down** and keep the "front and slightly above" wording.
3. **The outline wording differs**: "single color black outline" (characters) vs "single color outline" (map objects). Both ship.
4. **Monsters are too dark on dark floors.** Rat and slime fell below the 3:1 body-edge rule and needed a recolour on 2026-10-15. New monsters must be **lighter than you'd expect**: a mid value with a lit rim on the top-left.
5. **Things that don't move yet.** Monster idles, NPCs, peers, torches and the waterwheel are single frames (fps 0). It's a known gap, not a style choice.
6. **Hero facings.** The hero has 4 facings and the target is 8; monsters need only E and W.
7. **Item icons that look small.** 59–94% fill today. Flat items (fish, bars) look small: draw them on the diagonal.
8. **The docs say "record seeds", but no sidecar has a seed.** Seeds were never saved (see §2.4).
9. `ASSET_MANIFEST.md` still holds the old painted-art section, marked superseded. Ignore it.

## 2. The PixelLab workflow as actually used

All world art was generated through the **PixelLab MCP/API** (tool names below), never through the website. Every accepted world asset records its tool, job id and request in its sidecar.

### 2.1 Tools used (VERIFIED, counted over the 124 world sidecars)
| Tool | Used for | Count |
|---|---|---|
| `create_character` mode `v3`, size 40 | hero, 3 peers, 2 NPCs | 6 |
| `animate_character` mode `v3`, custom `action_description`, one direction per call | hero idle/walk/attack/down | 4 clips |
| `create_object_pro_flash` (`n_directions: 8` for monsters, 1 for objects) | rat, slime, hive_wasp, chest, door | 5 |
| `animate_object` mode `v3` | monster walk/attack/hit/death | 4 per monster |
| `create_1_direction_object` (one call returns a sheet of 64 candidates; one is picked) | most props, clutter, decals, hanging objects | ~60, from 3 batch jobs (`b90e189e` cellar 32 px, `53ef2fe1` cellar 16 px, `8304f632` town/home 32 px) |
| `create_map_object` | big or special props: trees, well, waterwheel, bed, hearth, forge, counter, statue | ~22 |
| `create_topdown_tileset` mode `pro`, tile 32 | `town_ground` (cobble↔grass), `cellar_floor` | 2 |
| `edit_image` | recolouring rat and slime (one consistent edit over all 27 frames) | 4 calls |
| `pixelart_workbench` / hand edits (free) | hero walk foot fix, loot bag | — |
| **Not PixelLab**: hand-authored with a seeded procedural brush, palette-native | every wall, wall cap, stub, roof, `cellar_earth`, `plank_floor`, `rug` | ~25 |
| `create_image_pixen` | all 506 item icons (according to `ASSET_MANIFEST.md`) | 506 |

### 2.2 Settings (VERIFIED)
- **Characters:** `body_type: humanoid`, `mode: v3`, `size: 40` (body ≈36 in a 64 frame), `view: "high top-down"`, `outline: "single color black outline"`, `detail: "high detail"`. The prompt always ends with *"grown-up adult proportions, gritty muted (earthy) colours, standing idle facing the viewer"*.
- **Monsters:** `create_object_pro_flash`, `view: "high top-down"`, `n_directions: 8`, `width/height: 24` (rat, wasp) or `32` (slime). The prompt ends with *"high top-down RPG monster, (strong) dark outline, detailed shading, muted gritty colours"*.
- **Monster animations:** `animate_object` v3. walk 6 frames, attack 6, hit 4, death 6. The corpse is the last death frame. West is east mirrored.
- **Prop batches:** `create_1_direction_object`, `size: 32` (16 for small clutter and decals), `view: "top-down"`, a shared batch `description` plus a per-item `item_description`, then a candidate index.
- **Map objects:** `view: "high top-down"`, `outline: "single color outline"`, `shading: "detailed shading"`, `detail: "high detail"`, width/height a little above the target frame. The prompt always ends with *"muted colours, dark outline, no shadow, no floor/ground"*.
- **Tilesets:** `create_topdown_tileset`, `tile_size 32×32`, `transition_size 0.25`, `view "high top-down"`, generation `mode: "pro"`, `text_guidance_scale: 8`, `tileset_adherence: 100`, `tileset_adherence_freedom: 500`, `spread_x 0.5`, `raggedness 0.5`, `slope_size 0`, `tile_strength 1`. Style detail/outline/shading were left null.

### 2.3 Reference features
- **Init images / character references:** not used for any shipped character. Each was made from text only, then kept consistent through its persistent `character_id` and animation groups. The pipeline *recommends* `reference_image_url` (a straight-south sprite) for new humanoids in the existing style.
- **Style references:** used **once**: `chest` drew its style from a barrel candidate (`style_image: "batch candidate b24/c42"`). The prop batches got their consistency from **one shared batch description**, not from style images.
- **Inpainting:** recommended for props that must fit a spot (`create_map_object` + `background_image` + `inpainting`), but no shipped sidecar records an inpaint.
- **Edit:** `edit_image` across many frames at once (rat, slime).

### 2.4 Not recorded (so not reproducible exactly)
- **Seeds: none recorded, for any asset.** The same prompt will give a *similar*, never identical, result.
- **Guidance scale** is only recorded for tilesets (8). Characters and objects used PixelLab's defaults; the values are NOT RECORDED.
- **Negative prompts:** none were used. Negatives are written into the prompt as plain text ("no shadow, no floor, not isometric").
- **The 506 item icons:** the tool (`create_image_pixen`), "one fixed seed and one shared prompt per family" and the palette snap are documented, but **the prompts and seeds were not saved** anywhere in the repo. To match them, use an existing icon as the style reference (§4.6). The older painted pilot prompts in `docs/design/art-pilot-prompts.md` are for Recraft and the painted style. **Don't use them.**

### 2.5 After generation (VERIFIED, `tools/world-art/*`)
PixelLab output **is not final**. Claude's pipeline does three things:
1. **Palette lock**: grade by material, then snap every pixel to the 56 colours in Lab space, and cut alpha at 128 (`lock.mjs`).
2. **Measure** against the size class and contact rules (`validate.mjs`, `tests/world-assets.mjs`).
3. **Pack** into the atlas (`build.mjs --set <set>`).

You don't need to do any of this. Export clean PNGs into `art/inbox/` and Claude runs it. Getting the art as close as possible before export (right size, muted colours, no shadow, one outline) is what decides whether it passes.

## 3. Standards per asset category

The frame is the canvas size and the anchor is the contact point (where the feet meet the ground). All art has a transparent background except terrain.

| Category | Canvas | Body (measured) | Views needed | Animation |
|---|---|---|---|---|
| **Hero, NPCs, humanoid monsters** | 64×64, anchor (32,58) | 36–40 px tall | 8 facings, s se e ne n nw w sw (only s e n w are shipped today) | idle 4–6f @5fps loop · walk 8f @10fps, both feet lift, contact poses at f0 and f4 · attack 6–7f @12fps with a hit frame · hit 3–5f · down 6–7f, holds the last frame |
| **Critters** (rats, slimes) | 48×48, anchor (24,40) | 12–20 px (larger side) | E (W = mirror) | idle 4f @5 · walk 6f @8–10 · attack 6–7f @12 · hit 5f · death 6–7f, last frame = corpse |
| **Fliers** | 48×48, anchor (24,44) | 12–20 px (narrow side), hovers 6–16 px | E | as critters |
| **Beasts** (wolves, boars) | 64×64, anchor (32,56) | 40–48 px wide | E | as critters |
| **Bosses** | **no class exists yet.** Ask Claude to add a row in `art-budget.js` first; a boss never goes in a critter frame | — | E | as critters |
| **Weapons, armour, inventory items** | 32×32, transparent | the object fills 75–94%; weapons on a diagonal, blade/head upper-left, grip lower-right | one | none |

| **Bushes** | ≤32 | 12–28 tall | one | none |

| **Buildings** | made of 32×60 wall slices, roof slices and a door (48 tall). **Not generated as one picture.** Walls are hand-drawn by Claude's procedural brush | | front face | none |
| **Furniture** | per class: table 20–24 tall, seat 24–28, bench 12–20, bed 40–60, station 22–32 | | one front view | none |
| **Decorations / trophies** | `hanging` class 6–40 tall (hung on walls), or `clutter` | | front | none |

Rules for every category: no baked shadow, no ground under the object, binary alpha, one dark outline, lit from the upper left, nothing below the contact row except a declared overhang (a tail).

## 4. Manual PixelLab guide (beginner)

### 4.0 Before anything
- **Website vs API.** Everything in §2 was done through the API/MCP (`api.pixellab.ai`). The website exposes most of the same generators through its web app, but **I couldn't confirm the exact menu names** (UNVERIFIED). Find tools by *what they do*: "create character", "animate", "create object / map object", "tileset", "image from text with a style image", "edit/inpaint". If the website doesn't offer a setting listed here, use the closest one and say so in your notes file.
- **API-only (as far as I know):** the 64-candidate prop sheet (`create_1_direction_object`), passing our exact palette, multi-frame `edit_image`, appending facings to an existing character's animation group by id, and Pro Flash objects. For those, either ask Claude later, or use the website alternative given.
- **Always:** set the view to **high top-down** whenever there's a view option, choose a **single-colour (black) outline**, **detailed shading**, **high detail**, and a **transparent background**.
- **Keep a log.** For each export, write a `<name>.txt` next to it in `art/inbox/` with the tool, size, prompt, reference used and seed (if the site shows one). This fixes the gap in §2.4.

### 4.1 Characters (hero gear variants, NPCs, humanoid enemies)
1. Open the **character creator** (website: likely "Create Character").
2. Settings: humanoid · size **40** (or the canvas that gives a 64×64 frame) · view **high top-down** · outline **single color black outline** · detail **high** · directions **8** (4 if 8 isn't offered).
3. Reference: if it accepts a reference/init image, upload `art/reference/characters/hero_idle_s@4x.png` (straight south is required). For a new person, text only is how every shipped character was made.
4. Prompt: template **T-CHAR** (§5).
5. Animate: open the **animate** tool on that character. Choose a **custom action** (v3), not a template; templates redrew the hero and lost his shield. Do one direction at a time and paste the **identical** action text for every direction. Frames: idle 4, walk 8, attack 6, down 6.
6. Check at ×2 that gear never appears or disappears between frames and the feet stay on the same row.
7. Export each direction as a PNG strip (or individual frames). Name: §8.

### 4.2 Monsters and bosses
1. Website: the object generator with directions (on the API this is **Pro Flash**, `create_object_pro_flash`, which may be API-only). Website fallback: "create character" for humanoid or quadruped monsters (templates: bear, cat, dog, horse, lion), or the object tool for small creatures.
2. Settings: view high top-down · size **24** (critter/flier) or **32** (blob) on a 48 canvas; **48–56** for beasts on a 64 canvas · 8 directions (only E is required).
3. Reference: `art/reference/monsters/rat_idle_e@4x.png` as style image if accepted.
4. Prompt: **T-MON**. Keep it **mid-value**: "lighter X fur, lit rim along the top and upper left". Give each family one signature accent colour on ≤15% of the pixels.
5. Animate (custom actions, the same text for every frame set): walk 6, attack 6, hit 4, death 6 (ends lying flat and still).
6. Export the **east** facing (Claude mirrors it for west).

### 4.3 Weapons, armour and inventory icons
1. Website: image generation with a **style reference image** (API: `create_image_pro` with `style_image_url` and our palette, or `create_image_pixen`). Canvas **32×32**.
2. Reference: upload the closest family icon from `art/reference/icons/` (sword → `iron_sword`, armour → `bronze_platebody`, ore → `iron_ore`, food → `cooked_trout`, drops → `rat_tail`).
3. Prompt: **T-ICON**.
4. **Tiers stay one set:** for every tier of the same item line (bronze→iron→steel→mithril), keep the prompt *identical* except the material words, and reuse the same seed if the site shows it. That's how the shipped tiers were made.
5. Metals: iron, steel and mithril read cold grey to silver-blue; bronze and gold read warm.
6. Export a 32×32 PNG named after the item id (§8).

### 4.4 Trees, rocks, ores, gathering nodes
1. Website: the **map object** generator (API `create_map_object`).
2. Settings: view high top-down · outline single colour · detailed shading · high detail · size: tree 92×120, rock/ore node 32–40.
3. Reference: `props/oak@4x.png` (trees), `props/barrel@4x.png` (small objects).
4. Prompt: **T-ENV**, and always "no shadow, no ground, no grass".
5. A depleted node is a second generation of the same prompt with "depleted/stumped", using the first output as the style reference.
6. Note: rocks and ore nodes have no size class yet. Claude adds one when it ingests the first.

### 4.5 Furniture, decorations, trophies, housing props
1. Website: the map object or single-object generator. API best: `create_1_direction_object` with a **shared batch description**, which gives 64 candidates in one style.
2. Settings: size 32 · high top-down (the props used `top-down` plus wording; see §1.1) · single colour outline · detailed shading.
3. Reference: the nearest of `props/chair`, `bed`, `hearth`, `weapon_rack`, `trophy_wolf`.
4. Prompt: **T-HOUSE**. *Keep the batch sentence word for word*; change only the item.
5. **Reject anything corner-on or diamond-shaped**: the validator rejects isometric corners (a rug and two chests were redone for this).

### 4.6 Buildings
Don't generate whole buildings. Walls and roofs are hand-built slices. What you *can* make: doors (28×52, `create_object_pro_flash` or map object with "straight front view, fills the doorway, no wall around it"), signs, window boxes and chimneys as `hanging`/`fixture` props. To propose a new building, make one **concept** image (any size) and put it in the inbox labelled `concept_`. Claude cuts it into slices.

### 4.7 Terrain and tilesets
1. Website: the **top-down tileset** generator (Wang / corner tileset). API `create_topdown_tileset`.
2. Settings: tile 32×32 · view high top-down · transition size 0.25 · (API also: pro mode, guidance 8).
3. Write a lower material, an upper material and a transition (template **T-TILE**). Say "flat", "no grid or tile pattern" and "set flush".
4. Chain tilesets: when the site offers "use the base tile of an existing tileset", start from the existing one so the shared material matches.
5. Export the 16-tile sheet (4×4 of 32 px = 128×128) plus the generator's tile order if it gives one.

### 4.8 UI icons and illustrations
Not a PixelLab job in this game (chrome is code-drawn; control icons stay line SVGs). A UI icon that shows an *object* (a coin, a potion) is an item icon: §4.3.

### 4.9 Variations without losing the style
- Change **only the subject words**; never touch the style tail of a template.
- Always upload the same reference for the same family.
- Reuse the seed for tiers or recolours (if shown); change it for different objects.
- Batch similar things together (one sitting, one reference).
- Make 5, look at them beside the reference at ×2, then do the rest in groups of ≤20 (CLAUDE.md §10).

## 5. Prompt templates

Replace `{…}`. Don't edit the text outside the braces. The tails are copied from shipped requests.

**T-CHAR — character** (from hero, peers and NPCs)
```
{role and age}, {main garment and material}, {second garment / cloak and colour}, {weapon or tool and which hand}, {footwear}, grown-up adult proportions, gritty muted earthy colours, standing idle facing the viewer
```
Settings: humanoid · v3 · size 40 · high top-down · single color black outline · high detail.
Example (shipped): `burly middle-aged village blacksmith with a short dark beard, rolled-up sleeves, scorched leather apron over a grey shirt, heavy hammer in hand, grown-up adult proportions, gritty muted colours, standing idle facing the viewer`

**T-ANIM — character animation** (use the same text for every direction)
```
{action in present participle}, {what each hand holds, stated explicitly}, {secondary motion: cloak swaying / tail swaying}
```
Example: `walking forward at a steady pace, sword held low in the right hand and shield on the left arm, cloak swaying`

**T-MON — monster**
```
{size word} {habitat} {creature} monster, {body colour, lighter mid-value} with {lighter underside}, {one signature feature in its accent colour}, {eyes}, {feet/limbs}, {pose}, light catching along the top of the back from the upper left, high top-down RPG monster, strong dark outline, detailed shading, muted gritty colours
```
Settings: high top-down · 8 directions · 24×24 (critter/flier) / 32×32 (blob) / ~48 (beast).
Monster animation texts (shipped):
- walk: `{creature} {moving verb} forward {how}, {secondary}`
- attack: `{creature} lunging forward and {biting/striking}, then pulling back`
- hit: `{creature} flinching backwards from a hard hit, then steadying`
- death: `{creature} collapsing onto its side and lying dead and still on the floor`

**T-ICON — weapon / armour / item icon (32×32)**
```
pixel art inventory icon of {one object} made of {material}, {one or two defining details}, {weapons: on a diagonal, blade upper-left, grip lower-right | flat items: drawn on the diagonal}, centred and filling the frame, single dark outline, light from the upper left, muted earthy colours, {metal rule: cold grey-blue steel | warm bronze}, transparent background, no shadow, no ground, no text
```
*(Built from the documented icon rules. The original icon prompt was NOT RECORDED. Upload a family icon as the style reference.)*

**T-HOUSE — furniture / decoration / trophy** (batch sentence copied verbatim from job `8304f632`)
```
prop for a grounded medieval town and a timber house interior in a top-down RPG, seen from the front and slightly above, muted earthy colours, dark outline, detailed shading, not isometric, no shadow
```
Item line: `{object}, {material}, front view`. Example items shipped: `wooden chair with a tall back, front view`, `wolf head trophy mounted on a wooden plaque`, `anvil`.
For a hunting ground, swap in the cellar batch sentence (job `b90e189e`): `prop for a dark medieval {place} in a top-down RPG, seen from the front and slightly above, upright, muted earthy colours, dark outline, detailed shading, standing on the floor, not isometric`

**T-ENV — trees, rocks, ores, big props (map object)**
```
{object with size and character}, {main material and colour}, {secondary detail}, top-down RPG {object type} seen from the front and above, muted {dominant colour}, dark outline, no shadow, no ground, no grass
```
Settings: high top-down · single color outline · detailed shading · high detail.
Example (shipped oak): `old oak tree with a broad dense rounded crown of dark green leaves, thick gnarled brown trunk with roots, top-down RPG tree seen from the front and above, muted deep greens, dark outline, no shadow, no ground, no grass`

**T-TILE — terrain**
```
lower: {material}, {texture: irregular / organic}, {small details}, no grid or tile pattern
upper: {material}, {shape of pieces}, set flush in the ground, {wear}
transition: {what happens at the edge}
```
Example (shipped town): lower `worn grey cobblestone street, irregular rounded stones with dark gaps and a little dirt between them` · upper `short dark muted green grass with small tufts, no flowers` · transition `grass growing between loose edge cobbles`.

Names to avoid in subjects: Shadow, Void, Ancient, Eternal, Dark, Forgotten as names (CLAUDE.md §10). "Dark" as a colour word is fine.

## 6. Approval checklist (before you drop a file in the inbox)
1. Viewed at **×2 next to its reference**: same outline weight, same muted colours, same light direction.
2. 3/4 top-down, front face visible, **not** corner-on or isometric.
3. Right canvas and body size for its class (§3).
4. **No shadow, no ground, no grass patch, no glow, no soft edges.**
5. Animations: same gear in every frame, feet on one row, the same action text for all facings.
6. Monsters: the body clearly lighter than a dark floor (put it on `prototypes/world-shell/shots/phase2/cellar-fight-desktop.png` mentally: does it vanish?).
7. Icons: fills 75–94% of 32×32; tiers look like one set.
8. No colours outside the swatch's feel (neon, pure white, pure saturated primaries). Claude snaps to the palette, but far-off colours snap badly.
9. A `<name>.txt` log next to it (tool, settings, prompt, reference, seed).
10. Name follows §8.

Claude then runs the gates you can't: palette lock, `tests/world-assets.mjs`, `tests/pixel-icons.mjs`, the in-game ×2 look, and the registry row in `ASSET_MANIFEST.md`.

## 7. Reproducibility walk-through: a variant of the cellar barrel

**The original (VERIFIED, `art/world/cellar/barrel.json`):** API `create_1_direction_object`, job `b90e189e`, candidate 0, size 32, view `top-down`, batch description *"prop for a dark medieval mill cellar in a top-down RPG, seen from the front and slightly above, upright, muted earthy colours, dark outline, detailed shading, standing on the floor, not isometric"*, item *"upright wooden barrel with iron hoops, front view"*. Then cropped to 24×32, anchor (12,30), material `wood` (graded ×0.8 sat, ×0.92 value), snapped to the palette. No seed was recorded.

**Making a "water barrel with a ladle" by hand:**
1. Open the website's object / map-object generator. Canvas 32×32 (use 24×32 if custom sizes are allowed).
2. View **high top-down**, outline **single color outline**, shading **detailed**, detail **high**, transparent background.
3. Style/reference image: `art/reference/props/barrel@4x.png`.
4. Prompt: the cellar batch sentence above + `, upright wooden water barrel with iron hoops and a wooden ladle hooked over the rim, front view`.
5. Generate 4. Reject any that are corner-on, have a shadow, or are taller than ~28 px. Pick the one whose hoops and outline match the reference at ×2.
6. Export a PNG → `art/inbox/cellar__barrel_water.png` + `cellar__barrel_water.txt`.
7. Claude crops it, palette-locks it as `wood`, checks it in the `barrel` class (24–28 px tall), and builds.

**How this differs from the automated path:**
- The automated batch pulled 64 candidates from *one shared description*, so every prop in a sheet shares one hand. By hand you get a few at a time, and **the style reference image does that job instead**. Always attach it.
- The API used `view: "top-down"` plus wording. The website may only offer presets, so use high top-down.
- No seed exists for the original, so the variant will be **consistent, not identical**.
- The palette snap and size checks happen after the inbox, not in PixelLab. Small colour drift is fixed automatically; perspective, shadows and size are not.

## 8. Naming and hand-off
- Inbox file: `<set>__<id>.png`, where set = `town | home | cellar | hero | items | <new ground>` and id = `snake_case`, equal to the game's data id when one exists (`rat` = `MONSTERS.rat`; an icon = its `ITEMS` key, e.g. `items__steel_dagger.png`). Variants are suffixes (`barrel_old`), never numbers.
- Animations: `<set>__<id>__<clip>_<dir>.png` as a horizontal strip, e.g. `hero__hero__walk_se.png`, `cellar__bat__attack_e.png`. Clips: idle, walk, attack, hit, death (monsters) / down (characters).
- Concepts not meant to ship: prefix `concept_`.
- Every file gets a `.txt` log with the same name.
- Don't put files in `art/world/`, `assets/` or `art/reference/`.
