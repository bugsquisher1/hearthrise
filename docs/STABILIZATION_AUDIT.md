## Playtests completed
- 2026-09-04 b501 live (QA account): reload → fight (~15 goblin kills, manual ticks) → stop → reload → compare; forge refusal branch; desktop screens Home/Inventory/House/Combat read; 922×423 via visual-qa.mjs. Found SA-001 (measured), SA-016.

**SA-001 ACCEPTANCE CRITERIA (set 2026-09-04 from the phase-2 critic + my own source read — apply these when reviewing the lane):**
1. **"Attended" MUST be derived SERVER-side.** `away: true` is hard-coded at THREE sites in `supabase/functions/hr-accrue/accrual.js` (:1374, :1876, :2225) — the engine has no attended concept. The derivation must come from server evidence inside the window (e.g. `hr_credit_kills` / `hr_credit_combat_xp` rows), NEVER from a client predicate. A client that simply never claims attendance must not be able to choose which side settles it, or the bug survives one branch over.
2. **One definition only.** If the loot credit and the food debit use different notions of "attended", the reported bug returns on the untested path. Same predicate, same commit.
3. **Food/HP reconciliation.** The `eat` verb takes a client-named item and the client has ALREADY applied the heal locally during an attended fight (`src/legacy.js:8483` holds the meal when `_clientOwnsAutoEatDebit()` is false). A server-computed heal on the same meal double-heals or diverges `player_state.hp`. The fix must state how HP reconciles, and the heal magnitude needs a security line.
4. **Rate gate.** `hr_rate_ok` gates the kill-credit path (`2026-08-30-bounty-kill-credit.sql:357`, rejecting `rate_limited`). Cadence is 60s (`HR_KILL_CREDIT_MS`/`HR_COMBAT_XP_MS`). Moving loot onto that RPC and adding forced flushes must not trip the bucket — a silent rate refusal reproduces the exact under-credit symptom the fix is named for. Requires a load-shaped assertion plus an `hr_rejections` watch.
5. **Edge-redeploy ordering.** This needs a redeploy, but `live-hash-drift` is currently RED with `hr_record_rejection` / `hr_state_of` live≠replay unexplained. Do NOT redeploy until that is EXPLAINED (not merely re-pinned), or the one artefact that says what changed is destroyed on the day the economy changes.
6. **Rollback.** This is the only change that can mint items for every player at once. It needs a named revert artefact (previous Edge bundle hash), a `player_ledger` rate-of-credit watch, and it must bake on the pre-wipe tree through at least one full play-gate before the wipe ceremony.
