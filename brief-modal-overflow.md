## 1. VERIFIED ROOT CAUSE
Both skeptics held it, and I re-read every line below at 715a9b1d.

**The card has no height cap.**
- legacy.css:2114 `.welcome-overlay{position:fixed;inset:0;...display:none;align-items:center;justify-content:center;padding:20px}`, and :2115 sets `.show{display:flex}`.
- legacy.css:2117 `.welcome-modal{max-width:480px;width:100%;...padding:24px}` has no max-height and no overflow.
- The only mobile rule is audit-overrides.css:2791, inside the query at :2661. It changes width and padding only.

**Why it spills off both edges.**
- A centred flex item taller than its container spills evenly above and below: top = (771−40−1179)/2+20 = −204. That matches the live measurement exactly.
- legacy.css:24 sets `html,body{height:100%;overflow:hidden}`, so nothing can scroll: not the wheel, not a swipe.
- The markup at legacy.js:13718-13730 puts the head, `#welcome-rows` (filled at :13645) and Continue in one box with no scrolling region.

**Why Escape does nothing.**
- The global handler at legacy.js:6998-7004 calls closeAllModals (legacy.js:6980-6994), which never lists `.welcome-overlay`.
- legacy.js:9458 handles only `.modal.show`.
- The only way out is the backdrop click (legacy.js:13728). On a 922x423 phone the card is 882 px wide (audit-overrides.css:2791 `max-width:calc(100vw - 24px)`), which leaves a 20 px strip on each side.

**Class cause.** The game has no modal primitive. Each overlay picks its own `Nvh` cap (or none), its own scroll region (or none) and its own Escape handling (or none).

**Corrections already folded in (do not re-litigate):**
- What's New caps at 85vh = 655/612/360 px (border-box, legacy.css:23). It fits, but the whole card scrolls, so "Got it" (welcome-modal.js:112) is at the end of the scroll.
- Row estimate: about 51 px per row. At 922x423, 4 or more rows probably overflow. This is unmeasured, so your test forces overflow rather than trusting this number.
- The characters list, monster preview and bank panel run 7/14/6 px past their padded box but stay on screen at 922x423. That is a P3 gutter issue, not part of this P1, so do not expect them to go RED.
- The bug-form Escape skip at legacy.js:7000-7001 is dead code. `#hr-bug-modal` never gets `.show` (bug-report.js:627-630). It exists only while open, because its close() removes the node (bug-report.js:647). Today, Escape with the bug form open closes whatever `.modal` is underneath it.
- `currentBuildKey()` (welcome-modal.js:22-26) is also the What's New seen-key (welcome-modal.js:142-157). Change the pill's DISPLAY only, never the key.
- One Escape can close two layers. HearthriseDialog (utils/dialog.js:124-125, :145) and the daily sheet (daily-reward.js:527, :551) handle Escape in the capture phase with `preventDefault`, but the global handler still runs `closeAllModals()` after them.

### Design: a LAYOUT-ONLY primitive
- **No `display`.** The owners keep their own open contract (`.show`, node insertion, inline flex). If `.hr-scrim` set `display:flex`, art-direction.css would beat `.welcome-overlay{display:none}` and leave a permanent full-screen layer. That would be a P0.
- **No skin.** No background, border or colour. The welcome card keeps its 3 px gold border.
- **No z-index.** Every owner keeps its own stacking.

**(a) src/styles/tokens.css, in the `:root` block near `--safe-*` (tokens.css:340-343):**
```
--modal-gutter: clamp(8px, 2.5vmin, 20px);
```
This needs no media query.

**(b) src/styles/art-direction.css, as a new appended section.** It loads after legacy, audit-overrides and theme-cozy (index.html:165-172):
```
.hr-scrim{position:fixed;inset:0;box-sizing:border-box;padding:max(var(--modal-gutter),var(--safe-t)) max(var(--modal-gutter),var(--safe-r)) max(var(--modal-gutter),var(--safe-b)) max(var(--modal-gutter),var(--safe-l));overflow:hidden;overscroll-behavior:contain}
body[data-hr-desktop-mode] .hr-scrim{top:var(--hr-dm-banner-h,0px)}
.hr-sheet{max-height:100%;min-height:0;display:flex;flex-direction:column;overflow:hidden}
.hr-sheet-head,.hr-sheet-foot{flex:none}
.hr-sheet-body{flex:1 1 auto;min-height:0;overflow-y:auto;overscroll-behavior:contain}
.hr-sheet-body>*{flex-shrink:0}
```
Why each piece:
- `max-height:100%` of the scrim's fixed content box replaces every `Nvh` guess, and it cannot overshoot the padding.
- The primary action lives in the foot, so it is on screen at scroll 0.
- The desktop-mode banner is fixed at top:0 with z-index 2147483647 (desktop-mode-detector.js:163-164). Its height is published on documentElement at desktop-mode-detector.js:121-124. The `top` rule keeps the sheet's head out from under it, which is the same fix art-direction.css:386-389 already applies to the dungeon-run overlays.
- `>*{flex-shrink:0}` stops a child that has overflow set (for example the Hearthfind band prepended at legacy.js:13645) from collapsing to 0.

**(c) NEW file src/render/modal-sheet.js.** It is an IIFE classic script, loaded in index.html with `?v=555` right after `src/utils/dialog.js` (index.html:1017) and before legacy.js (index.html:1101). It exposes `window.HearthriseSheet = { topOpen, closeTop }`:
- An element is **open** if it is connected and its computed style has `display != none`, `visibility != hidden`, `pointer-events != none`, and `getClientRects().length > 0`.
- **topOpen()** returns the open `.hr-scrim` with the highest computed z-index. On a tie, the later one in the DOM wins.
- **closeTop()** does this:
  - If no sheet is open, return false.
  - Otherwise click the top sheet's `[data-hr-dismiss]` control, if it has one, and return true.
  - Returning true even when there is no dismiss control means Escape is consumed and never falls through to close a layer underneath.

**(d) The ONE Escape seam: rewrite legacy.js:6998-7004 in place, keeping the same 7 lines.**
```
document.addEventListener('keydown', function(e){
  if(e.key === 'Escape' && !e.defaultPrevented){
    if(document.getElementById('hr-bug-modal')) return; // form keeps its typed text; node exists only while open
    if(window.HearthriseSheet && window.HearthriseSheet.closeTop()){ e.preventDefault(); return; }
    closeAllModals();
  }
});
```
Then delete ONLY line 9458, the `if(e.key==='Escape'){...;return;}` duplicate. Keep lines 9457 and 9459-9463: the 1-8 tab hotkeys and 's' to save live in the same listener.

**Do NOT put any `.hr-scrim` logic inside closeAllModals.**
- showTab calls it on every navigation (legacy.js:7076), including programmatic ones.
- The suite's harness also calls it (_harness.js:61, smoke-test.js:192).
- Putting the logic there would dismiss the away receipt on any tab change. WELCOME_GATE never re-opens a dismissed card (legacy.js:13683-13684).

**Never put `data-hr-dismiss` on a committing control:** the daily sheet's Claim, the KO sheet's actions, or a confirm's Yes.
