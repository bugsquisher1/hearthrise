## Verdict: **EDGE DEPLOY GO-WITH-CHANGES**

There is one required change, and it has landed on `sec/settle-before-mutate-f1`, so **merge that branch instead of the lane**. The change: **the party fence's "second class" skipped the settle on a false premise.** Party hunts run in SHADOW today. `hr_party_tick_settle` moves no member watermark there (`2026-09-24-m8-parties-s4-2-hunt-intents.sql:10-15`), and the hunt window is paid **after the stop** by the member's own settle, at the state that exists then (same file, 88-96). `hr_party_hunt_start` is granted to `authenticated` (line 722), so the dark hunt screen protects nothing. With the lane as written, a player can start a hunt with a friend, idle overnight, eat a Hunter's Feast or buy a rung (the settle is skipped), stop the hunt and then accrue. The whole hunt is paid with the buff. That is F1's mint, still reachable.

**The fix** (party-fence.js): add `PARTY_CHANNEL_PAYS = false`. While it is false, a partied settle-before-mutate verb is refused `party_hunt_running`, the same way a switch is. The skip comes back only when S5 arms the channel. The pre-S2 `42883` degrade is unchanged. There is a new pin, **S4b**, in `tests/absence-priced-at-return.mjs`, with the mutant `partyOwnsWhileShadow`. `--mutate` now catches **6/6**. `tests/party-settle.mjs` F2b was updated to match.
