## Design: Presence horizon, the B1 ruling (backend, 2026-10-08 UTC, lane/b566-gather-widen). **STAGED, NOT APPLIED; SQL half before edge half; both before stage 1**
**Ruling (Game Designer):** option (b). N = `hr_offline_cap_ms`, measured from the LAST REAL RETURN. The armed tick pays nothing past R + N. The return pays `max(0, min(absence, N) − tick-paid)`. One rule for every armed character, QA included.

**Mechanism.** **R** = `hr_return_anchor.real_return_at`. AFTER triggers on `player_state` stamp it to the new `accrued_to` whenever a transaction that is NOT the tick moves `accrued_to`. The tick is recognised by the transaction-local `hr.frame_origin='tick'` that `hr_tick_settle`/`hr_party_tick_settle` set at (0b) before any write, so a tick settle can never move R. An unticked character always has R = `accrued_to`, so nothing changes for it. **Tick:** `hr_tick_settle` (8d) runs after 8b/8c, under the player lock, and uses the same `hr_offline_cap_ms` as 8c. A window ending after R + N is refused `past_horizon`, not clipped. No anchor means `no_return_anchor` (fails closed). **Return:** `hr_accrue_cap_ms` = least(N, R + N − `accrued_to`); tick-paid time is `accrued_to` − R, so this is exactly the ruling's formula. The engine pays [`accrued_to`, +that] and forfeits the tail, just as an over-cap tail is forfeited today. If the absence's budget is spent (< 60 s left, the engine floor) and now() is past R + N, the function closes the absence itself: one `hr_apply` that moves only `accrued_to` → now(), journalled `accrue/horizon_forfeit` with an idempotency key derived from (user, slot, R). Without it the engine would answer `below_min_span` forever and R would never move. A partied character is never touched (invariant 8).
**Proven (guard + §8 self-check, PGlite replay):** away 20 h with cap 12 h is paid tick 12 h + return 0 = 12 h. Tick 5 h then an outage: the return reads exactly the 7 h remainder.
