## Design: Presence horizon, the B1 ruling (backend, 2026-10-08 UTC, lane/b566-gather-widen). **STAGED, NOT APPLIED; SQL half before edge half; both before stage 1**
**Ruling (Game Designer):** option (b). N = `hr_offline_cap_ms`, measured from the LAST REAL RETURN. The armed tick pays nothing past R + N. The return pays `max(0, min(absence, N) − tick-paid)`. One rule for every armed character, QA included.
**Files:** `2026-10-10-world-tick-presence-horizon.sql` (in the chain, BEFORE widen; widen's §0 now refuses unless this file's `hr_tick_settle` 512cdc65 is installed). Edge half: commit 10344aa4, four reads in `index.ts`/`set-activity.js`/`claim-reward.js`/`spend.js` change `hr_offline_cap_ms` → `hr_accrue_cap_ms`. It is kept out of tonight's c5eef77a; pack hash with it is `820b941c`. Guard: `node tests/world-tick-presence-horizon.mjs [--mutate]` (H1-H8 + E1, 11 mutants, mutant-control registered).
**Mechanism.** **R** = `hr_return_anchor.real_return_at`. AFTER triggers on `player_state` stamp it to the new `accrued_to` whenever a transaction that is NOT the tick moves `accrued_to`. The tick is recognised by the transaction-local `hr.frame_origin='tick'` that `hr_tick_settle`/`hr_party_tick_settle` set at (0b) before any write, so a tick settle can never move R. An unticked character always has R = `accrued_to`, so nothing changes for it. **Tick:** `hr_tick_settle` (8d) runs after 8b/8c, under the player lock, and uses the same `hr_offline_cap_ms` as 8c. A window ending after R + N is refused `past_horizon`, not clipped. The first refusal per absence writes one `hr_tick_horizon_log` row (the character is PARKED: still owned, still rostered, refused with no rows written). No anchor means `no_return_anchor` (fails closed). **Return:** `hr_accrue_cap_ms` = least(N, R + N − `accrued_to`); tick-paid time is `accrued_to` − R, so this is exactly the ruling's formula. The engine pays [`accrued_to`, +that] and forfeits the tail, just as an over-cap tail is forfeited today. If the absence's budget is spent (< 60 s left, the engine floor) and now() is past R + N, the function closes the absence itself: one `hr_apply` that moves only `accrued_to` → now(), journalled `accrue/horizon_forfeit` with an idempotency key derived from (user, slot, R). Without it the engine would answer `below_min_span` forever and R would never move. A partied character is never touched (invariant 8).
**Proven (guard + §8 self-check, PGlite replay):** away 20 h with cap 12 h is paid tick 12 h + return 0 = 12 h. Tick 5 h then an outage: the return reads exactly the 7 h remainder. Never ticked: the full 12 h, the same total. Attended: a settle carries R, and the next armed window pays. Clan level 7 (15 h): tick and return both use 15 h. Mutants caught: no horizon; anchor from the last tick; no offset on return (double pay); a fence cap ≠ accrue's; a return cap ≠ accrue's; no forfeit; no-anchor pays; partied forfeited; `hr_tick` granted; edge reading the raw cap (×2).
**Order.** Apply the SQL first: the tick is fenced at once, but the edge still reads the raw cap, so a ticked character's NEXT return can be paid up to the tick-paid time again, for that one absence only (operator cohort only: QA slot 2). Then deploy the edge bundle. Then widen. Never deploy the edge before the SQL: `hr_accrue_cap_ms` missing = 42883 = every accrue 500s. The backfill gives QA slot 2 R = 2026-10-07 16:33:54 UTC (its last non-tick gather accrue), so it parks at R + 12 h.
**V-checks added:** V10, the forfeit rows (`intent='horizon_forfeit'`): at most one per (character, anchor), and `meta.forfeit_ms` ≈ now − horizon at the return. V11, per armed character, Σ tick `meta.ms` since R ≤ N. The lag judge (`hr_tick_stall_status` and vitals `ARMED_LAG`) treats PARKED as not stuck (widen W6/W12 + 2 mutants). V4 must exclude `past_horizon`, which is an expected refusal while parked.
**Limitations / follow-ups:** the party path is not horizon-fenced (combat is unarmed; M4's arm must add (8d) to `hr_party_tick_settle`). A parked character is still rostered and refused every fire; lane b566-tick-scale's due-only roster should skip windows ending past the horizon (`hr_return_anchor` + `hr_offline_cap_ms`). Up to 60 s of an absence is forfeited when a parked character returns below the floor. `hr_accrue_cap_ms` writes once in the read transaction, so the request that forfeits gets one `version_conflict` and the next poll is correct (no pay crosses it). live-hash-drift will want `hr_tick_settle` 512cdc65, `hr_assert_grant_hygiene` (link 17) and `hr_tick_stall_status` d9a30e8e after apply.

**S1, due-only roster.** The roster claims only characters with `mark <= now() - flush`, on the same mark the fence compares.
