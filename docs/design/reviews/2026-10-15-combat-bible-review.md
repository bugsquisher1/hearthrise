## 4. Phase 1 contracts
**4.1 Ability rows** (`src/data/abilities.js`; frozen rows; server catalogue generated, like supply-basics):
`{ id, n, family:'melee'|'ranged'|'destruction'|'restoration'|'universal', skill:'melee'|'ranged'|'magic', lane:'offense'|'heal_spell', cdMs, manaPct (of baseMana(L)), magicXpMult, rune:{family,qty}|null, minRuneTier:null, target:'self'|'enemy'|'ally'|'area', effect:{kind:'damage'|'heal'|'shield', mult|healPct, flat}, unlock:{skill,lv}, autoDefault:{conds} }`
- Weapons gain `discipline` (staff → destruction, rod → restoration). Availability = `family ∈ {weapon.discipline, 'universal'}`. Never keyed on an item id. `ally`/`area` validate but are refused at v1 (single-target engine, pull clamped to 1).
**4.2 Cast event and XP (one engine).** Inside `simulateTick`'s successor, the order is: validate weapon/family → walk the bar for the first eligible ability → check target (heal needs missing HP > 0) → check mana ≥ cost, rune in bag or permitted store, lane ready, ability cd ready → debit mana and rune (shop buy via buyFromShop) → apply the effect → grant XP → emit a cast event into the tally/ledger.
- `magicXp = manaSpent × K × magicXpMult`. Heals use **effective** mana = manaSpent × min(1, healed/healMax), so overheal pays nothing.
- K is derived from ruling U's table: Level XP/h ÷ maxMana is 216/226/199/206 at L10/50/100/200, almost flat. With U's 12%/min regen (7.2 × maxMana/h), K ≈ 29 Magic XP per mana keeps a regen-only caster at melee parity (UNV until U7 runs).
- Restoring mana gives 0. Invalid or free casts give 0 XP and 0 debit (test).
- Seed label per event: `hunt:<session>:<tq>:<lane>`, so the result never depends on where a settle window splits. The same function runs for tick, settle and press; no `ctx.away`.
**4.3 Cadence inside the settle.** A fixed quantum Q = 100 ms (UNV; any divisor of the interval and every lane value). The session stores `swing_index` (exists) and `cooldowns{consumable,heal_spell,offense}` as absolute ms (the jsonb exists).
- In each quantum, resolve in a fixed order: consumable → heal_spell → offense → basic attack (if the quantum hits a swing boundary) → monster attack (same universal boundary). At most one event per lane per quantum, one basic attack per boundary.
- SQL fuse (stateful, like Security gather item 1): basic swings = ⌊(to−t0)/I⌋ − ⌊(from−t0)/I⌋ exactly; casts per lane ≤ ⌈window/laneMs⌉ measured from the stored next-ready; anything over is refused (`xp_fuse`).
- Offline parity is by construction (TICK-1: N ticks equal one span).
**4.4 Armour weight.** `armourMods(equipment, items) → { hpPct, manaPct, hpRegenPct, manaRegenPct }`. Pure, in src/core, the only reader of `weight`. Per-slot units as in U (body 2, others 1). Max and regen are separate fields (Bible PROPOSED). Prayer multiplies regen only: `regen = base × (1+armourRegenPct) × (1+prayerBonus(P))`, with prayerBonus asymptotic (e.g. 0.20·P/(P+60), UNV).
**4.5 Prayer bone transaction.** Bones mint as loot during the hunt (journalled, session_id). The action set carries `bones: keep|offer_all|offer:[ids]`. At the session's end, in the SAME transaction that returns the bag, `hr_offer_bones` removes the qty and grants Σ qty × server catalogue `buryXp` to Prayer, under one intent key `offer:<session>` (unique; a retry is a no-op). A town "Offer bones" press calls the same function with key `offer:<user>:<ledger_seq>`. The regen bonus reads Prayer at session start, so nothing loops inside a hunt.
**4.6 Store vs My Supplies.** Each bar slot names a LINE (heal, mana, arrow, `rune:fire`), not just an item.
- Resolve a line as: carried bag item of the line, at the slot's tier preference, never a higher tier than configured. If none is left: mode store, or mine + on_dry store → the shop basic of the line, priced and debited atomically in hr_hunt_apply (exists, re-priced server-side). Mine + end, with an essential line → the hunt ends `<line>_out`.
- A rune ability with `minRuneTier` above Basic skips the cast instead of downgrading.
- Analyzer split = tally.supply_gold (store) vs tally.supplies (units carried in). Both exist.

## 6. Pushback (DESIGN_STANDARDS §10)
1. **Gold → Magic XP.** Store drinks make Magic XP purchasable; melee buys only survival. The offense lane's cooldown is the hard ceiling (casts/h × cost × K). Hold that ceiling at parity, and price store drinks so a store-fed caster's XP/h ≤ a crafted-fed one's.
2. **Ship 3 abilities per discipline, not 6.** 6 × 4 + universal + 6 rune families is a large authoring and balance surface before Phase 3 data exists. Ship each discipline's identity ability plus 2; AoE and Challenge wait for multi-pull (the engine is single-target today).
3. **No elemental monster weaknesses in v1.** Families are an economy (which rune you craft), not a swap chore across 10 bag lines. Keep the existing style weakness only.
4. **Configuration is a retention risk.** Every weapon ships with a pre-filled default rotation (identity ability, then the filler, self-heal ≤50% HP, cheapest food ≤50%). A new player never opens the editor to hunt well.
5. **A universal interval flattens weapon feel.** Give each family a distinct damage shape (hammer: higher max, lower accuracy) inside the parity guard, so the hammer still feels like a hammer without being faster or slower.
6. **Restoration solo floor.** Make it a guard, not a hope: Restoration kills/h ≥ 70% of Destruction at the reference hunt (PROPOSED number).
7. **Show the server's events.** The 100 ms quantum can be replayed by the client from the settle's event list. Animate from that list; never predict casts (CLAUDE.md §6).
